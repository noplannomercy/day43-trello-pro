## Day 35 실행 프롬프트

### Phase A용 (Phase 1-11: 백엔드)

```markdown
specs/IMPLEMENTATION.md, CLAUDE.md, specs/ARCHITECTURE.md 읽기

## Phase {N} 실행 (Backend)

### 실행 방식
coder-expert 서브에이전트 배포하여 구현

### 구현 규칙
1. Phase {N} 섹션 전체를 먼저 읽고 시작
2. "Files to Create" 목록 순서대로 구현
3. "Implementation Strategy" 단계별로 따르기
4. Context7 MCP로 최신 문서 참조 (Next.js App Router API Routes)
5. ARCHITECTURE.md의 Request/Response 형식을 정확히 반영

### 빌드 검증
파일 3개마다:
```bash
npm run build
```
- 에러 0개여야 다음 진행
- 에러 발생 시: 즉시 수정 → 재빌드 → 계속
- 동일 에러 3회 실패 시: 보고 후 중단

### curl 테스트 (매 Phase 완료 후 즉시)
- npm run dev 실행 상태에서 테스트
- IMPLEMENTATION.md Phase {N}의 curl 명령어를 순서대로 실행
- 각 응답이 ARCHITECTURE.md의 예상 형식과 일치하는지 확인
- ⚠️ 비즈니스 규칙 에러 케이스도 반드시 테스트
  - Phase 5: 시간표 충돌, 정원 초과→대기자 전환
  - Phase 6: 휴일 출석 차단, 결석 없는 보강 차단
  - Phase 7: inactive 수납 차단, 환불 제약
  - Phase 9: 중복 대기 차단, 정원 확인

- 각 단계의 응답 ID를 다음 단계에 사용

#### 시나리오 2: 정원초과→대기자→수강전환
- 정원 1명 반 생성 → 2명 등록 시도 → 대기자 확인 → 취소 → 전환

#### 시나리오 3: 결석→보강→완료

#### 시나리오 4: 수납→환불

#### 시나리오 5: 대시보드 정합성
- totalStudents, monthlyRevenue, unpaidCount 등 수치 검증
