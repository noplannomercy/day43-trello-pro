Create specs/IMPLEMENTATION.md:

Phase-by-phase implementation plan with checkboxes.

Each Phase include:
1. Goal
2. Estimated time
3. Files to create (checklist format)
4. Implementation strategy
5. Testing checkpoint (checklist)
6. Acceptance criteria (checklist)

Phase structure (Backend First 전략):

### Phase A: Backend (API + DB)
- ARCHITECTURE.md의 API 목록 기반으로 Phase 분리
- 각 Phase 완료 후: npm run build + curl 테스트

### Phase B: Frontend (UI)
- COMPONENTS.md의 컴포넌트 목록 기반으로 Phase 분리
- 각 Phase 완료 후: npm run build + E2E 테스트 (playwright-test MCP)

### Phase C: 최종 검증
- 전체 E2E 시나리오 테스트
- SRS_FINAL.md의 주요 사용 시나리오 기반

CRITICAL CONSTRAINTS:
- Backend First: Phase A 완료 후 Phase B 시작
- Phase A: curl 테스트 명령어 + 예상 응답 JSON 필수
- Phase B: 각 Phase 완료 후 E2E 테스트 프롬프트 + 체크리스트 필수
- Phase C: 전체 E2E 시나리오 테스트 (SRS 시나리오 기반)

⭐ Phase A curl 테스트 포맷:
```bash
# [API 설명]
curl -X [METHOD] http://localhost:3000/api/[endpoint] \
  -H "Content-Type: application/json" \
  -d '[request body]'

# 예상 응답:
# [response JSON]
```

⭐ Phase B E2E 테스트 포맷:
```
E2E 테스트 (playwright-test MCP):
"[기능명] E2E 테스트해줘.
URL: http://localhost:3000
시나리오:
- [테스트 항목들]
통과할 때까지 수정."

테스트 체크리스트:
- [ ] 시나리오 1 통과
- [ ] 시나리오 2 통과
```

⭐ Phase C 전체 E2E 시나리오:
- SRS_FINAL.md의 "주요 사용 시나리오" 섹션 기반
- 각 시나리오별 E2E 테스트 프롬프트 작성
