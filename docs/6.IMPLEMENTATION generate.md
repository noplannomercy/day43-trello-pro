## 구조 (Backend First 전략)

### Phase A: Backend (API + DB 전체)
- P0: 인증, 멀티보드, 리스트, 카드 API
- P1: 라벨, 마감일 API
- P2: 멤버, 활동로그 API
- 각 Phase 완료 후: npm run build + curl 테스트

### Phase B: Frontend (UI 전체)
- P0: 인증, 보드목록, 보드화면, 리스트, 카드, 사이드패널
- P1: 라벨, 마감일 UI
- P2: 멤버, 활동로그 UI
- 각 Phase 완료 후: npm run build + playwright-skill E2E
- ⭐ 테스트 파일 저장 필수: tests/phase-b[N].spec.ts

### Phase C: 최종 검증
- 전체 E2E 실행: npx playwright test
- SRS 시나리오 기반 검증

## 각 Phase 포맷
- Goal
- Estimated time
- Files to create (체크박스)
- Implementation strategy
- Testing (curl 또는 E2E 프롬프트)
- Testing Checklist (체크박스)
- Acceptance Criteria (체크박스)

## 중요
- Backend First: Phase A 전체 완료 → Phase B 시작
- Phase A: curl 테스트만
- Phase B: playwright-skill E2E + tests/*.spec.ts 저장 필수
- Phase C: npx playwright test 실행만
